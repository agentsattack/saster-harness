# Handoff — novel mutants (Protocol A, step 5), under the exclusion discipline

Written 2026-09-06 for a separate session that seeds 5–10 NEW defects into this harness, blind: it must not have seen the catalogue below, the defect log, the rejection suite, or any report. The kill rate on those mutants is the generalization claim for the checklist; a mutant that reproduces a catalogued row is not novel and is excluded when scored.

- `saster_defense/` (the five layers, the OPA and z3 clients, the L1/L4 parsers), `carl_ops_envelope/` (the scorers), `carl_ops_assembly/assembler.py` and `carl_ops_trajectory/schema.py` (the record), `carl_ops_agent/` (the action plane), `saster_instrument/metrics.py` (the metrics), `scripts/run_cell_w9.py` and `scripts/run_sweep_w24.py` (the runner and driver).
- The spec docs only: `docs/grrcon-test-matrix.md` (pinned), `docs/envelope-preregistration.md` (pinned), `docs/instrumentation.md`.

## What the author must produce

- 5–10 branches `novel/N<k>` off `evidence/unprompted`, each a minimal code change (no test edits) that makes a wrong number plausible rather than an error: a silent default, a degenerate metric, a denominator, a unit, a wrong surface, a label, a scope, a serialization. One paragraph per branch in `NOVEL_README.md`: the change, the number it corrupts, the direction it leans.
- The author does not run the test suite. Scoring is done here with `scripts/mutation_score.py`, baseline and current trees, reported in `docs/mutation-score.md` as a third table.
